<section id="getting-started">

<h2>Getting started</h2>
 <p>Install MDK from npm in your project. This guide covers MDK {version}.</p>


```sh
npm install @tobiasoberpaul/mdk
```

 <h3 className="docs-subheading">Add the button and panel</h3>


```html
<button type="button" id="toggle-details"
  aria-controls="details" aria-expanded="false">
  Toggle details
</button>
<section id="details" aria-labelledby="details-title" hidden>
  <h2 id="details-title">Details</h2>
  <p>This panel opens and closes with a reversible Grow transition.</p>
</section>
```

 <h3 className="docs-subheading">Connect the transition</h3>
 <p>In your app’s JavaScript entry point, import the controller and CSS. This example assumes a bundler that supports CSS imports. Run the setup after the markup is mounted.</p>


```js
import { createGrowTransition } from '@tobiasoberpaul/mdk';
import '@tobiasoberpaul/mdk/motion.css';

const panel = document.querySelector('#details');
const button = document.querySelector('#toggle-details');

const transition = createGrowTransition({
  content: panel,
  reveal: [...panel.children],
  onStateChange(state) {
    if (state === 'destroyed') return;
    const expanded = state === 'opening' || state === 'open';
    button.setAttribute('aria-expanded', String(expanded));
    panel.hidden = state === 'closed';
    panel.inert = !expanded;
  },
});

const toggle = () => transition.toggle();
button.addEventListener('click', toggle);

// If the component unmounts, run this cleanup first.
function dispose() {
  button.removeEventListener('click', toggle);
  transition.destroy();
}
```

 <p>Click the button to open and close the panel. Clicking again mid-transition reverses it. Your component manages visibility and accessibility. The panel stays mounted until the exit animation finishes.</p>

<h3 className="docs-subheading">Grow a surface positioned by its component</h3>
<p>Use transform Grow without a trigger when the host owns placement. Logical origins follow text direction and writing mode. Forward the host’s open and close requests to the presence adapter.</p>

```js
import { createGrowTransition, createPresenceMotion } from '@tobiasoberpaul/mdk';

const motion = createPresenceMotion({
  stateTarget: surface,
  createTransition: lifecycle =>
    createGrowTransition({ content: surface, resize: 'transform', ...lifecycle }),
});
// Set --motion-scale-origin: inline-end block-start on the surface.
// Forward open and close requests to motion.setOpen(open).
// Unsubscribe and call motion.destroy() when the component unmounts.
```

<p>With <code>stateTarget</code>, keep the surface rendered at its normal open opacity while <code>data-motion-state="closing"</code>. Use <code>setPresent</code> when the host offers imperative presence control. For a host that hides immediately, omit both options and call <code>setOpen(true)</code> after the surface becomes visible.</p>

<p>Upgrading from the former Liquid API or markup? Use Extract when the source stays visible and Morph when the source becomes the target. Shared timing and geometry overrides now use <code>--motion-duration-transfer</code> and <code>--motion-transfer-*</code>.</p>

<section id="html-attributes">

<h2>HTML attributes</h2>

```html
<button id="trigger" aria-controls="target" aria-expanded="false">Open</button>
<section id="target" data-motion="grow"
  data-motion-trigger="#trigger" data-motion-anchor="top-right" hidden>
  <h2>Your next idea</h2>
  <p>The component owns its position and final dimensions.</p>
</section>
```

<p>Call <code>createMotion({'{content: target}'})</code> to read declarative attributes. It creates the animation controller; the integration still wires events, visibility and focus.</p>

<dl>
 <dt>data-motion</dt><dd>grow, extract, morph, slide or fade. Matching motion-* classes are also supported.</dd>
 <dt>Optional positioning</dt><dd>Use data-motion-relative-to="trigger", "viewport" or a container selector such as "#preview". Set data-motion-placement to center, top, bottom, left or right; append -start or -end for edge alignment. data-motion-space accepts a CSS length such as .75rem. Trigger placement is outside the trigger; viewport and container placement is inside the reference. Without these attributes, positioning stays component-owned. Placement and the animation anchor are independent.</dd>
 <dt>data-motion-anchor</dt><dd>auto, center, top, right, bottom, left or any corner such as top-right. Grow uses the origin; Extract and Morph use it for target overshoot. Auto infers alignment from measured geometry.</dd>
 <dt>data-motion-trigger</dt><dd>A CSS selector for the trigger. Required for Extract and Morph unless passed directly.</dd>
 <dt>data-motion-axis / data-motion-side</dt><dd>Constrain Grow to width or height; choose top, right, bottom or left for Slide.</dd>
 <dt>data-motion-reveal</dt><dd>Selector for inner content targets. Include headings, icons, labels, dividers and controls.</dd>
</dl>

</section>

<section id="interaction-triggers">

<h2>Interaction triggers</h2><p>Use the optional interaction layer to connect an animation to user input or screen entry. The component still owns positioning, presence, accessibility and focus. Keep existing component event bindings, or use this layer; avoid binding the same action twice.</p>

```html
<section id="target" data-motion="grow"
  data-motion-trigger="#trigger" data-motion-on="click"
  data-motion-dismiss="outside" data-motion-escape="true" hidden>
  ...
</section>

const transition = createInteractiveMotion({
  content: target,
  trigger,
  close: closeButton,
  onStateChange(state) {
    if (state === 'destroyed') return;
    target.hidden = state === 'closed';
    target.inert = state === 'closed' || state === 'closing';
  },
});
// Removes listeners, timers, observers and animation effects:
transition.destroy();
```

<h3 className="docs-subheading">Activation: data-motion-on</h3><div className="docs-table"><table><thead><tr><th>Value</th><th>Opens</th><th>Closes</th><th>Default</th></tr></thead><tbody><tr><td><code>click</code></td><td>Click, tap or native button keyboard activation.</td><td>Activate the trigger again.</td><td>Yes</td></tr><tr><td><code>hover</code></td><td>Mouse entry. Keyboard and touch use a click fallback.</td><td>Mouse exit after a short delay, once focus is outside both elements.</td><td>—</td></tr><tr><td><code>focus</code></td><td>Focus enters the trigger or target.</td><td>Focus leaves both trigger and target.</td><td>—</td></tr><tr><td><code>observer</code></td><td>Element enters the viewport (15% visibility by default).</td><td>Fully leaves the viewport, unless once is enabled.</td><td>—</td></tr><tr><td><code>scroll</code></td><td>Cross a scroll threshold or scrub across a start–end range.</td><td>Scroll back below the threshold or reverse through the range.</td><td>—</td></tr><tr><td><code>manual</code></td><td>Controller calls such as open() or toggle().</td><td>Controller calls or explicitly configured dismissal.</td><td>—</td></tr></tbody></table></div><h3 className="docs-subheading">Scroll activation</h3><p>Use data-motion-on="scroll" and data-motion-scroll-mode="trigger" or "scrub". Set data-motion-scroll-start and data-motion-scroll-end to absolute CSS pixel offsets, optionally within data-motion-scroll-root="#scroller". Trigger opens at the threshold and closes below it; data-motion-once="true" keeps it open. Scrub maps the range to timeline progress and reverses while scrolling back. Keep a stable layout slot. In TypeScript, bindScrollMotion with transition, root, start, end and mode: 'scrub' returns a cleanup function. Every controller also supports seek(progress) from 0 to 1. Reduced motion resolves to stable endpoints.</p><h3 className="docs-subheading">Dismissal and repetition</h3><div className="docs-table"><table><thead><tr><th>Attribute</th><th>Values</th><th>Behavior</th><th>Default</th></tr></thead><tbody><tr><td><code>data-motion-dismiss</code></td><td><code>outside</code> / <code>none</code></td><td>Close on an outside click, or require explicit closing. Use none for persistent dialogs.</td><td><code>none</code></td></tr><tr><td><code>data-motion-escape</code></td><td><code>true</code> / <code>false</code></td><td>Allow Escape to close the element.</td><td>true for click, hover and focus; false otherwise.</td></tr><tr><td><code>data-motion-once</code></td><td><code>true</code> / <code>false</code></td><td>Observer: reveal once, or reset after viewport exit and reveal again.</td><td><code>false</code></td></tr></tbody></table></div><p>For hidden observer targets, pass observeElement to observe a stable layout slot.</p><p>For an existing controller, call bindMotionInteractions with the existing controller and on: 'hover'. It returns an unbind function. Unbind before destroying the controller. The hover exit delay uses --motion-duration-hover-close (160 ms).</p>

<section id="content-and-timing">

<h2>Content and timing</h2><p>The default duration is 300 ms. Progressive reveal is enabled by default. Set --motion-content-progressive to 0 to disable it. Each page content item retains its full duration; progression adds a gap between start times.</p>

```js
target.style.setProperty('--motion-content-progressive', '1');
target.style.setProperty('--motion-content-stagger', '.08');
// Group related content and set its progression order:
// <div data-motion-content-group data-motion-order="1">...</div>
// data-motion-sequence="surface-first": surface starts before its contents.
const stop = observeMotion([{element: block, transition}], {
  threshold: .15,
  once: false, // true = animate only once
});
// On unmount: stop.disconnect(); transition.destroy();
```

<p>Repeated entry closes the block after it fully leaves the viewport. Layout space stays reserved. Use separate observers/controllers for independent blocks.</p>

<p>Tokens are read from computed styles. Overshoot uses a proportion of the shorter side, capped by the rem maximum. See the downloadable guide and motion.css for all semantic aliases.</p>

<section id="lifecycle-and-accessibility">

<h2>Lifecycle and accessibility</h2><p>The library respects prefers-reduced-motion and settles directly into a stable state. Decorative copies are inert and hidden from assistive technology. Use the component’s existing keyboard navigation, focus management, labels and dismissal behavior.</p><p>Keep aria-expanded synchronized, mark closed views hidden and inert, return focus when appropriate, and destroy controllers/listeners on unmount. Include every visible part in reveal groups. The consuming component remains responsible for its accessibility behavior.</p>

```js
const unbind = bindOutsideDismiss({
  elements: () => [trigger, target],
  enabled: () => transition.isOpen,
  onDismiss: () => transition.close(),
});
// On unmount: unbind(); transition.destroy();
```

<p>Outside-click dismissal is opt-in. Omit it for persistent dialogs. Screen-reader and real-device validation is still needed for each consuming application.</p>
